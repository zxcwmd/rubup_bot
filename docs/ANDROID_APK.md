# Нативный APK для рабочего Android-телефона

## Что это за вариант

`RubUP Worker` — самостоятельное Android-приложение, а не пульт и не веб-панель. Оно устанавливается на **второй, рабочий телефон с Android 10 или новее** и само выполняет поиск, чтение страниц TikTok, публикацию, проверку лайков, хранение истории и формирование ссылок.

Основной телефон нужен только для обычного Telegram-клиента. Он отправляет команды и изображения тому же Telegram-боту и получает статус, историю, ссылки и отчёты. Termux, proot, Chromium на ПК, root и отдельный сервер не нужны.

- package: `com.rubup.worker`;
- `minSdk=29` (Android 10), `targetSdk=35`;
- TikTok работает в постоянном Android WebView с сохранёнными cookies;
- Telegram работает через Bot API long polling;
- SQLite, одноразовые изображения и `links.txt` находятся в app-private хранилище;
- runtime-зависимости сторонних библиотек не используются.

> **Важно о проверке:** APK компилируется в GitHub Actions, но живой smoke-test на физическом телефоне с реальным TikTok/WebView ещё не выполнялся. Поэтому нельзя заранее гарантировать работу текущих селекторов TikTok, доступность фото в комментариях или непрерывную работу 24/7. Первый запуск делайте под наблюдением и проверяйте результат на самом TikTok.

## 1. Установка APK

1. На рабочем телефоне откройте [RubUP-Worker-debug.apk](../release/RubUP-Worker-debug.apk) или скачайте файл с основного устройства и передайте его на рабочий телефон.
2. Разрешите установку из этого источника, если Android запросит разрешение для браузера/файлового менеджера, и установите приложение.
3. Откройте **RubUP Worker**. Это debug-сборка: она подписана debug-ключом сборщика, а не выпускается как production-release. При обновлении APK с другой подписью Android может потребовать сначала удалить старую версию; удаление приложения также удалит его локальную базу, изображения и WebView-сессию.
4. При запросе разрешите уведомления. Постоянное уведомление нужно foreground-службе, которая выполняет работу в фоне.

Прямая ссылка на файл в этой ветке:

```text
https://github.com/zxcwmd/rubup_bot/raw/refs/heads/arena/514c6f72-rubup-bot/release/RubUP-Worker-debug.apk
```

Не передавайте APK вместе с токеном или данными приложения посторонним. В самом APK нет вашего Telegram-токена: настройки вводятся на телефоне после установки.

## 2. Первичная настройка на рабочем телефоне

В приложении заполните три поля:

1. **Telegram Bot Token** — токен бота, созданного через официального `@BotFather`.
2. **Ваш числовой Telegram ID** — ID администратора, не username. Можно указать несколько ID через запятую. Сообщения и callback-кнопки от других пользователей отклоняются.
3. **Логин TikTok без `@`** — точный логин единственного рабочего аккаунта. Он нужен, чтобы отличать свои комментарии от чужих и не отвечать самому себе.

Нажмите **«Сохранить и запустить службу»**. После этого:

1. Нажмите **«Войти в TikTok в WebView»**.
2. Во встроенном окне войдите ровно в один TikTok-аккаунт. Пароль вводится только на странице TikTok; приложение не просит отправлять его в Telegram.
3. Если TikTok покажет капчу или проверку безопасности, пройдите её вручную. Бот не обходит капчу.
4. В настройках Android разрешите приложению фоновую работу и неограниченное использование батареи. Для длительной работы держите рабочий телефон на зарядке и не закрывайте его принудительно через «Остановить».
5. Не запускайте одновременно Python/Termux-версию или второй экземпляр APK с тем же Telegram-токеном.

Сессия WebView сохраняется локально. Выход из TikTok, очистка данных приложения или удаление APK может потребовать повторного входа.

## 3. Управление с основного телефона

Откройте того же Telegram-бота и отправьте `/start`. Кнопки и команды доступны только указанным администраторам.

| Кнопка / команда | Действие |
|---|---|
| **▶️ Авто**, `/auto` | Включить автоматику и начать цикл |
| **⏸ Пауза**, `/pause` | Не начинать новые циклы; текущий вызов завершается |
| **⛔ Стоп**, `/stop` | Сразу запретить новые действия, дождаться текущего WebView-вызова и выгрузить WebView |
| **📊 Статус**, `/status` | Очередь, лимиты, публикации, лайки, ссылки и остаток картинок |
| **🔎 Найти видео**, `/discover` | Только поиск и проверка даты/тегов, без публикации |
| **🖼 Картинки**, `/images` | Показать состояние одноразовой библиотеки |
| **📝 История**, `/history` | Последние действия, статусы, лайки и ссылки |
| **🔗 Ссылки**, `/links` | Отправить актуальный `links.txt` документом |
| **📤 Отправить отчет**, `/report` | Отправить подтверждённые действия только в виде ссылок |
| **✅ Мой TikTok**, `/session` | Проверить сохранённую WebView-сессию |
| `/add ССЫЛКА` | Добавить конкретное TikTok-видео после проверки |
| `/set_tags тег1 тег2` | Полностью заменить список тегов |
| `/retry_like ID` | Повторно проверить лайк и завершить сохранение ссылки |
| `/retry ID` | Повторить только действие, которое отмечено как неопубликованное |

Можно также отправить боту полную ссылку на TikTok-видео. Неизвестные команды не запускают публикацию.

### Изображения

Отправляйте JPG/JPEG/PNG/WEBP боту прямо с основного телефона:

- **как документ/файл** — предпочтительно, чтобы Telegram не сжимал исходник;
- как фото — тоже поддерживается, но Telegram может изменить изображение.

Файл скачивается на рабочий телефон, проверяется как изображение и получает SHA-256. Одно и то же содержимое нельзя использовать дважды, даже если отправить его под другим именем. Максимальный размер импортируемого файла — 20 МБ. Исходники не подставляются из интернета и не выбираются повторно автоматически.

## 4. Правила публикации

### Основной комментарий

Цепочка строгая:

```text
новое локальное фото
  → предпросмотр фото
  → публикация и подтверждение своего комментария с фото
  → лайк именно своего комментария и подтверждение состояния
  → canonical URL в links.txt без дублей
```

Ссылка сохраняется только после подтверждённых фото и лайка. Если публикация или лайк не подтверждены, действие переводится на ручную проверку; автоматический повтор после неопределённого нажатия не выполняется. Ответы не лайкаются и не добавляются в `links.txt`.

Бот не создаёт второй основной комментарий на том же видео. Тексты проходят фильтр точных и похожих повторов, содержат явную пометку **«Реклама»** и не должны содержать благодарности за нереальные подарки. Шаблоны находятся в `android/app/src/main/assets/templates/`.

### Ответы

Ответ возможен только под чужим комментарием, который распознан по консервативным маркерам RubUP (`rubup`/`rub up`), не является похожим на уже обработанный и не принадлежит вашему аккаунту. Ответ отправляется без картинки. Если в реальных комментариях кампании нет такого машинно-распознаваемого признака, бот пропускает их, а не угадывает.

### Видео и дата

По умолчанию используются 27 тегов из `Models.kt`; их можно заменить через `/set_tags`. Видео должно иметь хотя бы один разрешённый тег и дату публикации **не раньше 1 мая 2026 года включительно** (сравнение по UTC). Если дату нельзя надёжно извлечь, видео пропускается.

## 5. Ручная проверка и отчёты

При неопределённом результате бот отправляет карточку с ID действия и ссылкой. Проверьте само видео, включая фото и авторство, прежде чем нажимать:

- **«Опубликовано»** — подтверждает факт публикации; для основного комментария затем используйте `/retry_like ID`, если лайк ещё не завершён;
- **«Не опубликовано»** — запрещает автоматическую выдачу этой же записи как успешной; повтор доступен только через явный `/retry ID` после проверки.

`/report` включает в отчёт только опубликованные ответы и полностью завершённые основные комментарии. Сообщение отчёта состоит только из ссылок, без текстов комментариев, скриншотов и имён авторов. Отдельные оплачиваемые действия на одном видео могут дать повторную строку с той же ссылкой — это не дубль внутри `links.txt`, а отдельная строка отчёта за другое действие.

Если отправка отчёта оборвалась, проверьте Telegram перед повторной отправкой: внешняя отправка и отметка «sent» не являются одной распределённой транзакцией.

## 6. Что делает «⛔ Стоп»

Stop немедленно выставляет запрет новых действий и отключает автоматику. Уже выполняющийся браузерный вызов не уничтожается посреди операции: служба ждёт освобождения browser lock, затем закрывает и выгружает WebView. Новые нажатия публикации/лайка после Stop не начинаются. Telegram-цикл остаётся активным, чтобы можно было снова нажать **▶️ Авто**.

Если Stop пришёл после фактического нажатия, результат сначала проверяется настолько, насколько это позволяет текущий вызов; неопределённая публикация не перезапускается автоматически.

## 7. Повторяемая сборка из исходников

Нужны JDK 17, Android SDK с platform `android-35` и Gradle wrapper из репозитория. На Linux/macOS:

```bash
git clone --branch arena/514c6f72-rubup-bot --single-branch https://github.com/zxcwmd/rubup_bot.git
cd rubup_bot/android
chmod +x gradlew
./gradlew --no-daemon --console=plain assembleDebug
```

Готовый файл появится здесь:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

SHA-256 опубликованного в репозитории APK записан рядом в `release/RubUP-Worker-debug.apk.sha256`; после скачивания можно сверить его командой `sha256sum RubUP-Worker-debug.apk`.

На Windows используйте `gradlew.bat assembleDebug` из каталога `android` при установленных JDK 17 и Android SDK.

GitHub Actions workflow `.github/workflows/android-apk.yml` повторяет эту сборку на Ubuntu с JDK 17. После сборки он загружает APK как artifact `rubup-worker-debug-apk` и публикует копию `release/RubUP-Worker-debug.apk` и `release/android-build.log` в текущую ветку. Для сборки не нужны Telegram-токен, TikTok-пароль или другие секреты.

## 8. Ограничения и диагностика

- **TikTok/WebView ещё не проверен вживую.** Селекторы находятся в `TikTokAdapter.kt`; если TikTok изменил DOM, нужно обновить адаптер и пересобрать APK. Не нажимайте публикацию многократно вручную для «проверки».
- Веб-версия TikTok может не предоставлять фото в комментариях для конкретного региона или аккаунта. Без подтверждённого предпросмотра бот не должен отправлять основной комментарий.
- Капча, истёкшая сессия и изменённый интерфейс переводят работу на паузу или ручную проверку. Откройте приложение и пройдите проверку вручную.
- Android может выгружать фоновые процессы несмотря на foreground service и wake lock. Проверьте батарею, автозапуск/фоновую активность, уведомления и питание. Это не гарантия круглосуточной работы.
- Для работы нужны одновременно доступные `api.telegram.org` и TikTok на рабочем телефоне. Проверьте сеть и системный VPN, если одна из них недоступна.
- Не очищайте данные приложения и не удаляйте его без необходимости: это удаляет SQLite, библиотеку изображений, файл ссылок и WebView-сессию. Перед экспериментом выгрузите ссылки через `/links`.
- APK является debug-сборкой для установки и проверки. После живого smoke-test можно отдельно подготовить release-сборку с собственным ключом.

Альтернативная схема с Termux/Ubuntu/Playwright сохранена в [docs/ANDROID.md](ANDROID.md), но для этого варианта APK она не требуется.
