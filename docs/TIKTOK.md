# Адаптер TikTok: проверка и обновление

## 1. Что делает адаптер

`rubup_bot/tiktok.py` использует Playwright и постоянный профиль Chromium. Он:

- открывает страницы тегов и собирает только URL формата `/@author/video/<id>`;
- удаляет tracking-параметры и отклоняет lookalike-домены;
- извлекает видео-метаданные из JSON (`__UNIVERSAL_DATA_FOR_REHYDRATION__`, `SIGI_STATE` и других `application/json`);
- читает видимые комментарии;
- заполняет поле, прикрепляет изображение при его наличии и один раз нажимает публикацию;
- ищет опубликованный текст в видимых элементах комментариев.

Никакие cookie, токены или пароли не печатаются в логи. Нет stealth-плагинов, ротации аккаунтов, подмены личности или обхода капчи.

## 2. Почему нужен первый ручной тест

TikTok может показывать разный DOM в зависимости от языка, региона, A/B-теста и возможностей аккаунта. В частности:

- фото в комментариях может быть доступно в мобильном приложении, но не в веб-версии;
- селекторы `data-e2e` и названия кнопок могут измениться;
- дата может отсутствовать в доступных JSON;
- комментарии могут подгружаться только после дополнительного действия;
- сессия может закончиться или потребовать проверку безопасности.

Отсутствие элемента не означает, что нужно многократно нажимать кнопки. Сначала проверьте возможность вручную.

## 3. `selectors.json`

Файл содержит именованные списки селекторов:

| Группа | Назначение |
|---|---|
| `challenge` | Видимая проверка безопасности |
| `logged_in` | Признак авторизованного интерфейса |
| `video_links` | Ссылки на видео на странице тега |
| `comment_items` | Контейнер одного комментария |
| `comment_author` | Логин автора внутри контейнера |
| `comment_text` | Текст внутри контейнера |
| `comment_reply_button` | Кнопка ответа |
| `comment_input` | Активное поле комментария/ответа |
| `image_input` | Файловый input для изображения |
| `image_preview` | Зарезервировано для предпросмотра загрузки |
| `submit` | Кнопка публикации |

Порядок важен: более точные `data-e2e` стоят первыми, общие CSS — последними. Не удаляйте точные варианты без необходимости.

### Как обновить селектор

1. Остановите автоматику.
2. Откройте видео в том же Chromium и включите DevTools.
3. Найдите стабильный атрибут нужного элемента, предпочтительно `data-e2e`, `data-testid`, `aria-label`.
4. Проверьте, что селектор соответствует нужному элементу, а не всем аватарам/кнопкам страницы.
5. Добавьте его первым в соответствующий список. Сохраните корректный JSON.
6. Установите дневные лимиты на 1, перезапустите бота и проверьте одно действие.
7. Не меняйте сразу несколько групп: иначе сложно понять причину ошибки.

Для проверки JSON без публикации:

```bash
.venv/bin/python -m rubup_bot doctor
.venv/bin/python -m rubup_bot discover
```

## 4. Дата публикации

Предпочтителен числовой `createTime` из объекта, у которого `id` совпадает с ID в URL. Поддерживаются секунды и миллисекунды Unix. Дата сравнивается в UTC с `MIN_VIDEO_DATE`.

Если дата найдена только у другого рекомендованного видео или её нет совсем, бот пропускает ролик. Это осознанный отказ от небезопасного предположения «раз нашли сейчас, значит новое».

## 5. Комментарии и стабильные ID

Адаптер читает `data-comment-id`, `data-cid`, `data-id` или числовой суффикс DOM ID. Если TikTok не предоставляет ID, используется детерминированный локальный хеш `(video_id, author, normalized_text)`.

Локальный хеш консервативно объединяет одинаковые комментарии одного автора на одном видео: бот скорее пропустит возможный ответ, чем ответит дважды.

## 6. Результат публикации

До нажатия кнопки ошибки обычно означают, что действие не отправлено. После нажатия результат считается неопределённым, пока текст не найден в комментариях.

Карточка ручной проверки содержит:

- ID действия;
- ссылку;
- текст;
- путь к выбранной картинке;
- причину;
- кнопки «Опубликовано» и «Не опубликовано».

Проверьте именно само видео, включая ответы при необходимости. Не ориентируйтесь только на исчезновение поля ввода.

## 7. Рекомендуемый живой smoke-test

1. Резервная копия `data/rubup.sqlite3`.
2. Одна новая тестовая картинка в `images/`.
3. `HEADLESS=false`.
4. `MAX_ACTIONS_PER_CYCLE=1`, оба дневных лимита 1.
5. Один известный подходящий ролик добавить через `/add`.
6. Включить автоматику и наблюдать за браузером.
7. Проверить текст, картинку, автора и отсутствие дубля на самом TikTok.
8. Подтвердить действие при необходимости, сформировать тестовый отчёт.
9. Только после успешного теста вернуть рабочие лимиты.

Если загрузка фото недоступна в веб-интерфейсе, автоматический основной комментарий с фото на этом аккаунте невозможен текущим адаптером. Бот оставит действие на ручную проверку; не следует выдавать текстовую публикацию без фото за оплачиваемую.
