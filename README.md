# RubUP Comment Bot

Telegram-бот для максимально автоматизированной работы с комментариями TikTok по правилам RubUP: один аккаунт, локальные одноразовые картинки, поиск по тегам, ответы под чужими RubUP-комментариями, история и отчёты в Telegram.

> **Практическое ограничение:** у TikTok нет общедоступного API для произвольной публикации таких комментариев, поэтому проект использует обычный Chromium через Playwright. Интерфейс TikTok и доступность фото в комментариях зависят от региона, аккаунта и текущей версии сайта. Если элемент не найден, появилась капча или результат нажатия не подтверждён, бот останавливает действие для ручной проверки, а не обходит защиту и не создаёт дубль. Перед рабочим запуском выполните небольшой тест на своём аккаунте и используйте автоматизацию только там, где она разрешена правилами площадки.

## Что реализовано

- Telegram-кнопки: запуск, пауза, поиск, статус, история, картинки, сессия TikTok, отчёты.
- Автопоиск видео по всем 27 заданным тегам с ротацией тегов между циклами.
- Проверка даты: принимаются видео **с 1 мая 2026 года включительно**. Если дату нельзя надёжно прочитать, видео пропускается.
- Один основной комментарий на видео; SQL-ограничение сохраняется после перезапуска.
- Обязательная новая картинка для основного комментария. JPG, JPEG, PNG и WEBP импортируются из локальной папки.
- SHA-256-дедупликация: одинаковое содержимое под другим именем не считается новой картинкой.
- Генерация текста по теме описания/тегов, фильтр точных и похожих повторов.
- Ответы без картинки только под чужими комментариями, распознанными как RubUP; один ответ на один исходный комментарий.
- Защита от ответа самому себе по `TIKTOK_USERNAME` и игнорирование похожих исходных комментариев.
- Явная пометка `Реклама` в каждом оплачиваемом тексте. Благодарности за неподтверждённые подарки по умолчанию запрещены.
- История действий, ручное подтверждение спорных публикаций и отправка отчёта только из ссылок.
- Один постоянный браузерный профиль и один TikTok-аккаунт. Мультиаккаунтность и обход капчи отсутствуют.

Архитектура и состояния описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), адаптация интерфейса — в [docs/TIKTOK.md](docs/TIKTOK.md).

## 1. Быстрый запуск на Windows

### 1.1. Установите Python

Нужен 64-битный **Python 3.11** или новее. При установке включите **Add Python to PATH**. Также понадобятся права на установку пакетов и скачивание Chromium.

### 1.2. Распакуйте и установите

1. Распакуйте ZIP в обычную локальную папку, например `C:\rubup-bot`.
2. Запустите `scripts\install.bat`.
3. Дождитесь установки Python-зависимостей и Chromium.

Скрипт создаст `.venv`, `.env`, `data` и необходимые папки. Не запускайте установку одновременно в нескольких окнах.

### 1.3. Настройте `.env`

Откройте созданный `.env` в Блокноте и замените как минимум:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
ADMIN_USER_IDS=ваш_числовой_Telegram_ID
TIKTOK_USERNAME=точный_логин_TikTok_без_собаки
```

- Токен Telegram создаётся через официального `@BotFather`.
- `ADMIN_USER_IDS` — числовой ID, не username. Для нескольких администраторов: `111111,222222`.
- `TIKTOK_USERNAME` должен точно совпадать с логином аккаунта: это защита от ответа под своим комментарием.
- Оставьте `HEADLESS=false` на время настройки и первого теста, чтобы видеть браузер.
- Не отправляйте `.env` и папку `data/browser-profile` другим людям.

### 1.4. Добавьте картинки

Сохраняйте исходники в корневую папку:

```text
images/
```

Можно складывать файлы сразу группами по 10. Бот импортирует их автоматически перед циклом или по кнопке **🖼 Картинки**. Исходники не удаляются; в `data/image-library` создаются неизменяемые копии с именем по хешу.

Не используйте `data/image-library` как входную папку и не меняйте там файлы вручную.

### 1.5. Войдите в TikTok

1. Полностью закройте работающего бота.
2. Запустите `scripts\login.bat`.
3. В открывшемся обычном окне Chromium войдите в **один** TikTok-аккаунт.
4. Если TikTok попросит проверку безопасности, пройдите её вручную.
5. После успешного входа вернитесь в консоль и нажмите Enter.

Пароль в Telegram или в код бота вводить не нужно. Сессия сохраняется локально в `data/browser-profile`.

### 1.6. Запустите и проверьте

1. Запустите `scripts\start.bat`.
2. Откройте своего Telegram-бота и отправьте `/start`.
3. Нажмите **✅ Мой TikTok** — должно появиться подтверждение сессии.
4. Нажмите **🖼 Картинки** — число новых картинок должно быть больше нуля.
5. Для первого теста временно установите в `.env`:

   ```dotenv
   MAX_ACTIONS_PER_CYCLE=1
   MAX_COMMENTS_PER_DAY=1
   MAX_REPLIES_PER_DAY=1
   ```

   Перезапустите бота после изменения лимитов.
6. Нажмите **▶️ Авто** и проследите первую публикацию в открытом браузере.
7. Если бот отправил карточку «Нужна ручная проверка», откройте видео, проверьте факт публикации и только затем выберите результат.

## 2. Запуск на Linux или macOS

```bash
cd /path/to/rubup_bot_project
chmod +x scripts/*.sh
./scripts/install.sh
nano .env                 # заполните токен, admin ID и TikTok username
# Сохраните изображения в images/
./scripts/login.sh        # нужен графический рабочий стол
./scripts/start.sh
```

Для Linux без системных библиотек Chromium может понадобиться:

```bash
.venv/bin/playwright install --with-deps chromium
```

Команда может запросить права администратора. На сервере без графического интерфейса первый интерактивный вход выполните на локальном компьютере; не переносите чужую сессию без понимания рисков.

Полезные команды из корня проекта:

```bash
.venv/bin/python -m rubup_bot doctor         # диагностика
.venv/bin/python -m rubup_bot import-images  # импорт картинок без запуска Telegram
.venv/bin/python -m rubup_bot discover       # один цикл поиска без публикации
.venv/bin/python -m rubup_bot login          # повторный вход
```

## 3. Управление в Telegram

| Кнопка / команда | Действие |
|---|---|
| **▶️ Авто**, `/auto` | Включить планировщик и начать цикл |
| **⏸ Пауза**, `/pause` | Не начинать новые циклы; текущая браузерная операция завершается |
| **📊 Статус**, `/status` | Очередь, лимиты, публикации, ошибки и остаток картинок |
| **🔎 Найти видео**, `/discover` | Только поиск и проверка даты, без публикации |
| **🖼 Картинки**, `/images` | Импорт новых файлов из `images/` |
| **📝 История**, `/history` | Последние 10 действий, статусы и ссылки |
| **📤 Отправить отчет**, `/report` | Отправить сообщение, состоящее только из ссылок |
| **🗂 Отчеты**, `/reports` | История сформированных отчётов |
| **✅ Мой TikTok**, `/session` | Проверить сохранённую сессию |
| **🏷 Теги**, `/tags` | Показать активные теги |
| `/set_tags cs2 caser нарезка` | Полностью заменить список тегов |
| `/add ССЫЛКА` | Проверить и добавить конкретное TikTok-видео |
| `/retry ID` | Повторить только действие, которое точно не опубликовано |

Можно также просто отправить боту полную ссылку на TikTok-видео.

### Как формируется отчёт

- Попадают только действия со статусом **«опубликовано»**: подтверждённые автоматически или вручную администратором.
- Каждая строка сообщения — только каноническая ссылка на видео, без автора, текста и скриншотов.
- Одна строка соответствует одному оплачиваемому действию. Поэтому если на одном видео есть оплачиваемый комментарий и отдельный ответ, одна и та же ссылка может стоять дважды — это намеренно.
- Уже отправленное действие повторно в новые отчёты не попадает.
- Если отправка сообщения не завершилась, отчёт остаётся `pending` и будет использован повторно. После частичной отправки проверьте чат, прежде чем нажимать кнопку снова.

## 4. Тексты и похожие комментарии

Шаблоны находятся в:

```text
templates/comments.txt   # основные комментарии
templates/replies.txt    # ответы
```

Одна строка — один шаблон. Доступны `{topic}` в обоих файлах и `{author}` в ответах. Не используйте неизвестные placeholder-ы. Новые строки читаются при следующей генерации.

Бот:

1. убирает пунктуацию/регистр для проверки точного повтора;
2. сравнивает новый текст с прошлыми действиями и видимыми комментариями;
3. отбрасывает варианты выше `SIMILARITY_THRESHOLD`;
4. не использует шаблоны с упоминанием RubUP;
5. добавляет `AD_DISCLOSURE`, если явной пометки ещё нет.

Если уникальных вариантов не осталось, добавьте новые содержательные строки в шаблоны. Не снижайте качество текстов ради количества.

### Благодарности за подарки

Фразы о полученных подарках отключены по умолчанию: `ALLOW_GIFT_CLAIMS=false`. Это предотвращает выдуманные благодарности. Только если каждое такое утверждение соответствует реально полученному вами подарку:

1. скопируйте `templates/gifts.example.txt` в `templates/gifts.txt`;
2. перепишите строки под свои подтверждённые случаи;
3. установите `ALLOW_GIFT_CLAIMS=true`.

## 5. Как бот находит комментарии для ответов

Произвольный текст или картинка не считаются достаточным доказательством принадлежности к RubUP. По умолчанию используется консервативное регулярное выражение:

```dotenv
RUBUP_COMMENT_MARKERS=rubup|rub\s*up
```

Если в реальных чужих RubUP-комментариях нет такого текста, задайте наблюдаемые устойчивые маркеры через `|`. Например, точную фразу, которая действительно присутствует только в проверенных комментариях кампании. Не задавайте общие слова вроде «бот», «спасибо» или «подарок»: они встречаются у обычных пользователей.

Для каждого кандидата дополнительно проверяется:

- автор не совпадает с `TIKTOK_USERNAME`;
- на этот исходный комментарий ещё не было ответа;
- похожий исходный комментарий ранее не обрабатывался;
- текст нового ответа не повторяет старые и видимые комментарии.

Если у ваших материалов нет машинно-распознаваемого маркера, полностью автоматическое и при этом безопасное определение чужих RubUP-комментариев невозможно; такие случаи требуют доработки источника признаков или ручной проверки.

## 6. Основные настройки `.env`

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `SCAN_INTERVAL_MINUTES` | 45 | Пауза между циклами |
| `MAX_TAGS_PER_CYCLE` | 4 | Сколько тегов проверять за цикл |
| `DISCOVERY_LIMIT_PER_TAG` | 8 | Максимум найденных ссылок на тег |
| `MAX_VIDEO_DETAILS_PER_CYCLE` | 20 | Максимум открытых страниц с метаданными |
| `MAX_ACTIONS_PER_CYCLE` | 4 | Максимум попыток публикации за цикл |
| `MAX_COMMENTS_PER_DAY` | 10 | Дневной лимит основных комментариев |
| `MAX_REPLIES_PER_DAY` | 20 | Дневной лимит ответов |
| `MAX_REPLIES_PER_VIDEO` | 2 | Лимит ответов под одним видео |
| `ACTION_DELAY_SECONDS` | 20 | Минимальная пауза между действиями |
| `ACTION_JITTER_SECONDS` | 15 | Дополнительная случайная пауза для планирования нагрузки |
| `MIN_VIDEO_DATE` | 2026-05-01 | Минимальная дата видео |
| `SIMILARITY_THRESHOLD` | 0.86 | Порог похожести создаваемого текста |
| `TARGET_SIMILARITY_THRESHOLD` | 0.92 | Порог похожести исходных комментариев |
| `HEADLESS` | false | Скрытое окно после успешной отладки |

После изменения `.env` перезапустите бота. Теги, изменённые через `/set_tags`, хранятся в базе отдельно.

## 7. Данные, резервная копия и безопасность

```text
.env                      # секретный Telegram-токен
data/rubup.sqlite3        # правила дедупликации, история, отчёты
data/image-library/       # неизменяемые копии картинок
data/browser-profile/     # секретная авторизованная сессия TikTok
```

Для полной резервной копии остановите бота и сохраните `.env` и `data`. Для переноса только истории без авторизации сохраните `data/rubup.sqlite3` и `data/image-library`, затем выполните вход заново.

**Удаление базы обнуляет защиту от повторов и историю отчётов.** Не запускайте два экземпляра бота на одной базе или браузерном профиле. Не храните рабочие секреты в Git и не отправляйте их в отчёты.

Изображение проходит путь `available → reserved → used`. После ошибки оно может остаться `reserved`: бот намеренно не выдаёт его для другого видео, потому что факт загрузки мог быть неизвестен.

## 8. Устранение неполадок

### `TELEGRAM_BOT_TOKEN ...` или Telegram 401

Проверьте токен от `@BotFather`. В `.env` не должно быть русского placeholder-а или лишних кавычек.

### `Conflict: terminated by other getUpdates request`

Запущен второй экземпляр этого Telegram-бота. Оставьте только один.

### Сессия TikTok не найдена

Остановите бота, выполните `login.bat`/`login.sh`, затем проверьте **Мой TikTok**. Не удаляйте `data/browser-profile` при обновлении кода.

### Капча или проверка безопасности

Автоматика ставится на паузу. Пройдите проверку вручную в обычном браузерном профиле и только затем продолжайте. Бот не содержит и не должен содержать обход капчи.

### Не найдена загрузка фото / поле / кнопка публикации

Сначала проверьте вручную, доступна ли функция в веб-версии именно у этого аккаунта. Если функция есть, но селектор изменился, обновите `selectors.json` по [docs/TIKTOK.md](docs/TIKTOK.md). Не подтверждайте публикацию, пока не увидели её на видео.

### Все видео пропускаются

Проверьте дату и теги. Видео без надёжно прочитанной даты пропускаются намеренно. Для проверки конкретной ссылки используйте `/add`.

### Нет новых картинок

Нажмите **🖼 Картинки** и посмотрите счётчики дубликатов/ошибок. Поддерживаются только JPG, JPEG, PNG и WEBP до 20 МиБ. Даже переименованный дубликат не будет использован повторно.

### Нет уникального текста

Дополните `templates/comments.txt` или `templates/replies.txt` своими содержательными вариантами.

## 9. Проверка проекта

```bash
# Linux/macOS
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check .
```

```bat
REM Windows
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest
.venv\Scripts\ruff.exe check .
```

Тесты используют имитацию TikTok и временные базы; они не публикуют реальные комментарии. Живой тест на своём аккаунте всё равно обязателен, потому что внешний интерфейс TikTok может отличаться.
